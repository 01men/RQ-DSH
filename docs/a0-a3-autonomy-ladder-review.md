## 1. 问题陈述

现状：`riskLevel read/write/admin` 是**能力分级**而非**授权等级**；连接器 `invokeAction`
只有"admin 恒审批 / 其他直接执行"的二元分叉。放权（autonomy）升级依赖功能清单评审，
而非覆盖 ODD 的运行证据。Agent 已带 `autonomy/runtime` 字段（IAW 7-1），但无分级行为语义。

## 2. 分级模型（A0–A3）

| 级别 | 名称 | 行为语义 | 前置条件 |
|---|---|---|---|
| A0 | 观测 | 产出候选调用（plan-only），一律不执行；dry_run 通道 | — |
| A1 | 建议 | 候选 + 影响面预览推送给人类，等待批准（现审批通道） | ODD 已声明 |
| A2 | 受控执行 | ODD 域内自动执行（read/write 且 riskCap 覆盖）；域外自动降级 A1 | ODD + 治理基线（P1 全层） |
| A3 | 有界自治 | ODD 域内自适应（含 admin 级带补偿的自动执行）；越界即熔断回 A2 并告警 | A2 运行证据达标 + 专项评审 |

不变式（红线）：
1. **放权永不越 ODD**：A3 的自治半径 = `odd` 声明块，未声明维度按最小放权处理。
2. **降级单向快、升级单向慢**：离域/告警即刻降级（无需人工）；升级必须走证据评审。
3. **补偿先于自治**：进入 A3 的每个 admin 级 kind 必须已注册补偿器（P2-02 注册表）。

## 3. 证据驱动放权（升级工件）

升级 A(n) → A(n+1) 的证据包（滚动 30 天，数据源全部已存在）：

| 证据 | 来源 | 门槛（建议初值） |
|---|---|---|
| ODD 覆盖调用占比 | `connector.invoked` 事件 × ODD 判定 | ≥ 95% 调用落在已声明 ODD 内 |
| 成功调用分布 | runs 对账（runtimeTokenId 维度） | 成功率 ≥ 99%，样本 ≥ 200 |
| 告警率 | `audit.alert.fired` / `connector.policy_mirror_failed` / 离域事件 | 离域 ≤ 1/周；镜像失败 = 0 未恢复 |
| 对账一致性 | usage 对账 + runs 交叉校验 | 偏差 ≤ 0.5% |
| 补偿演练 | P2-02 补偿注册表演练记录 | A3 候选 kind 全部演练通过 |

评审流程：证据包自动生成 → 架构师 + 业务负责人会签 → 审计留痕（`autonomy.elevation`
动作）→ 权限组 `autonomyLevel` 字段生效。降级无需会签。

## 4. 落地切片（当立项时）

1. `autonomyLevel` 字段进入权限组 + manifest（契约 lint 同步）；（~0.5 周）
2. invokeAction 分叉改造：A0 拦截 / A2 域内直通 / A3 admin 补偿路径；（~1 周）
3. 证据包生成器 + `autonomy.elevation` 评审留痕；（~1 周）
4. selftest：分级行为断言 + 降级即刻性断言 + 证据包口径断言。（~0.5 周）
