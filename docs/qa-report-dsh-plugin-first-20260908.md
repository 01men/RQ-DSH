## 0. 结论速览（TL;DR）

| 维度 | 结果 |
|---|---|
| 自动化基线 | ✅ selftest **1033/1033** + lint:manifests **85/85** 全绿 |
| 安全防线（向导头/代理白名单/票据一次性/口令重放） | ✅ SEC 组 7 项全 PASS（含路径穿越、方法变体、2MB 大包） |
| 主链路（装机→向导→连接→登录→工作台→持久化） | ✅ 冒烟 S1–S9 实测全通过 |
| 权限消费侧（RBAC-01/02/03/04） | ✅ 读/写/组织范围三级验证全通过，403 文案清晰 |
| **实时通道授权** | 🔴 **P0：SSE 流缺部门范围校验，组织受限用户可实时收到受限部门全部消息（已端到端坐实）** |
| dsh 会话侧注入 | 🔴 **P1：rq-card 浏览器半在真实 dsh web 上静默未挂载——「榕器工作台」视图 Tab / 设置分区 / 未连接角标全部缺失（两台实例复现）** |
| 一线班组长可用性 | ⚠️ 桌面大屏可用；**车间手机钉钉场景存在系统性差距**（10 项 P1：UTC 时间慢 8 小时、断网徽标失真、无超时、草稿丢失、触控热区过小、属性 XSS 等） |
| 出口判定 | ❌ **不通过**（P0=1，未达「P0=0」出口标准；P1 需闭环） |

**一句话总结**：交付质量的「骨架」是好的——自动化全绿、主链全通、安全防线扎实、权限模型在 REST 面执行正确；但存在 **1 个 P0 越权**（实时通道绕过部门范围校验）、**1 个 P1 注入失效**（会话侧能力整体静默缺失），以及一批对「车间真实场景」影响重大的体验缺陷。修复 P0 与注入问题前不建议交付现场。

## 4. 缺陷清单

> 定级遵循验收清单第 0 节：P0 主流程阻断/越权/串台；P1 功能缺陷但有替代路径；P2 体验与文案。
> 「实测确认」= 本轮有复现证据；「代码审查确认」= 有 文件:行号 级证据、建议修复后按 §5 对应目标复测。

### P0（1 项）

#### 🔴 BUG-A-01｜SSE 实时通道缺部门范围校验——组织受限用户实时收到受限部门全部消息（含正文）
- **环境**：E2 宿主 7300 · 人设 qa-pc（panel.read，属 QA-C 组织；rd 部门绑定 QA-B 组织）
- **复现**（已端到端坐实，证据 `docs/qa-evidence/sse-leak-qa-pc-rd.txt`）：
  1. qa-pc 登录取令牌；
  2. `GET /api/panel/rd/overview`（REST 面）→ **403「部门范围受限」**（REST 面执行正确）；
  3. `GET /api/panel/stream?dept=rd&token=<qa-pc令牌>`（SSE 面）→ **200 text/event-stream，连接建立**；
  4. 管理员往 rd 部门频道发消息 → qa-pc 的流里**实时收到完整事件**：`{"name":"panel.message.created","payload":{"dept":"rd","senderName":"平台管理员","text":"SECRET-CANARY-2-…"}}`。
- **根因**（T-EXPLORE-API R2）：`plugin-panel-core/src/index.ts:608-642` 的 stream 处理器只做 `verify(token)+requirePermission('panel.read')`，**从不调 `deptScopeAllowed()`**；且该端点经 `http.register` 注册、不进 routeMatrix，恰好逃出 selftest「RBAC 100% 越权断言网」（对照 ：106-115 REST 面的 deptOf 校验）。
- **影响**：属于组织 A 的任何 panel.read 用户可用 curl 持续监听组织 B 部门的全部新消息（含正文、发送人）。浏览器黑盒走查测不出（UI 会先被 overview 403 挡住），但直接打端点即越权——符合验收清单 P0 定义「越权/串台」。
- **建议**：stream 握手阶段复用 `deptScopeAllowed()` 做与 REST 一致的范围校验；并在 selftest 增加「对受限部门 stream 断言 403/断流」的越权回归（即新测试目标 T-01）。

### P1（实测确认，3 项）

#### 🔴 BUG-G-01｜rq-card 浏览器半在真实 dsh web 上静默未挂载——会话侧四项能力全部缺失
- **环境**：E1 3080（源码 patch 形态）与 3099（link 安装形态）**两台独立实例复现**

## 6. 产品视角：一线工人 / 班组长可用性评估

### 总评（可直接引用）

本面板对「坐办公室、桌面大屏、网络稳定」的使用者是可用的：三栏信息架构清晰、空态多数有兜底、消息白名单转义正确、localStorage 记忆普遍有服务端校验回退、**权限拒绝文案是全场最佳**（「权限点 panel.write，请联系管理员调整角色」——说清缺什么、找谁办）。工程底子不差。

但对「车间手机钉钉 + 不稳 WiFi + 戴手套」的一线真实场景存在**系统性差距**，可归纳为三条信任链断裂：

1. **数据可信链断裂**——时间按 UTC 显示慢 8 小时（BUG-U-01）、断网后 LIVE 徽标仍宣称实时（BUG-U-02）、请求无超时（BUG-U-03）：班组长**无法判断眼前的数据能不能用来派工**。对以「当班任务、交接班」为核心场景的用户，这是比崩溃更严重的缺陷——它制造静默的错误决策。
2. **手机端基本不可操作**——顶栏 375px 溢出、看板推进按钮约 18px 高、搜索在移动端整体不可达、正在输入的交接班草稿一切换就丢（BUG-U-07/08）。
3. **语言自内向外泄露**——从首启向导的「形态 B/免登命名空间」（BUG-U-09），到绑定弹窗的「事实源 identityLinks/入向 Stream（R-SPIKE）」，大量内部治理术语直接面向工人输出；加载失败甚至展示英文堆栈（BUG-U-10）。**一线用户不应该需要理解「宿主」这个词才能开始工作。**

另有一个安全侧的一线视角问题：属性 XSS（BUG-U-06）的注入点（任务场景编号、频道名）恰好是一线用户日常自由输入的字段，跨用户触发（同事建的任务卡出现在班组长看板上），应与 P0 同批修复。

**建议优先级**：P0（SSE 越权）→ 注入失效（BUG-G-01）→ 信任链三项（U-01/02/03）→ 属性 XSS + 草稿 + 触控（U-06/07/08）→ 文案语言轮（U-09/10 及 P2 术语项）。完成 P1 后，本面板方可从「演示可看」升级为「车间敢用」。

### 实测中的正面样本（保持并推广）
- 权限拒绝文案（见上）；会话失效引导（「与远端宿主的会话已失效。重新连接 / 登录」）；向导诚实指引（「无法跨站带回…请用账号密码登录」）；任务卡「→」快捷流转按钮（触屏友好，不依赖拖拽）；全部空态均有下一步指引；浏览器直开面板时礼貌的登录引导而非白屏。
