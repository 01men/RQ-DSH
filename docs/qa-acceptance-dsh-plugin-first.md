## 1. 被测产品形态（一图看懂）

```
【形态 B】单机自宿主                      【形态 C】客户端 dsh ──连接──> 远端宿主
┌─────────────────────────┐              ┌──────────────┐  本机代理    ┌────────────────────┐
│ dsh 单进程（本机即宿主）  │              │ dsh + 插件    │ /rqcard/proxy│ E2: 独立宿主 :7300  │
│ /rq/panel/ + hostBridge  │              │ /rq/panel/    │ ─────────>  │     （无 /rq 前缀） │
└─────────────────────────┘              │  令牌按连接隔离 │             │ E3: dsh 挂载宿主    │
                                          └──────────────┘             │     （/rq 前缀）    │
                                                                       └────────────────────┘
```

- **形态 B（E1 环境）**：面板/控制台/对话同进程，`hostBridge` 在场，SSE 直连。
- **形态 C（E2/E3 环境）**：本机 dsh 是客户端，面板 REST 全部经本机代理转发远端宿主，**鉴权与数据由宿主按登录账号强制**。E2 是用户现场形态（独立宿主，如 `192.168.x.x:7300`）；E3 的远端宿主本身也是装了插件的 dsh（前缀 `/rq`）。
- 关键机制：连接配置落盘 `<数据目录>/rq-host-link.json`；令牌键按连接隔离（`heng_ops_token` / `heng_ops_token@<宿主地址>`）；向导端点 `/rqcard/*` 免登 + 强制 `x-rqcard-call: 1` 头（CSRF 防线）。

## 2. 核心冒烟路径（约 30 分钟，P0 主链）

| # | 步骤 | 通过判据 |
|---|---|---|
| S1 | 全新数据目录启动业务 dsh（插件已装），打开 `http://127.0.0.1:3080/rq/panel/` | 渲染连接向导（双卡片：本机宿主 / 连接远端），控制台零红错 |
| S2 | 右侧输入独立宿主地址（如 `http://<宿主IP>:7300`）→「测试并连接」 | 显示「✅ 已连接宿主 …」+ 登录表单 |
| S3 | 输入宿主账号密码 →「登录」 | 页面重载后直接进入工作台；网络面板核对登录请求走 `/rq/rqcard/proxy/api/auth/login` |
| S4 | 工作台拉数据：部门/频道/消息 | 数据为**宿主侧**数据；请求路径为 `/rq/rqcard/proxy/api/panel/…`；请求带 `authorization` 头 |
| S5 | 点「💬 用钉钉扫码登录」备用入口 | 新标签打开 `${宿主}/?next=…#/login`（E2 地址**不含** `/rq`） |
| S6 | 回到向导点「我已在宿主页完成登录——校验本机会话」 | 出现诚实指引文案（无法跨站带回…请用账号密码登录），非报错栈 |
| S7 | dsh 会话页：视图 Tab 切到「榕器工作台」 | 面板整页内嵌（embed 形态），顶栏有外链 |
| S8 | dsh 对话里说「查看榕器宿主连接状态」 | `rq_host_status` 工具被调用，返回连接形态与面板入口 |
| S9 | 重启业务 dsh，再开面板 | 不再出向导，仍处于已连接态（进登录引导或工作台） |

### 4.7 安全边界（SEC，7 项）——curl 可直接验证

| 编号 | 优先级 | 步骤 | 预期 |
|---|---|---|---|
| SEC-01 | 🔴 | 无 `x-rqcard-call` 头请求任意 `/rq/rqcard/*` 端点 | 403 `WIZARD_CALL_HEADER_REQUIRED` |
| SEC-02 | 🔴 | 带头请求白名单外代理路径（如 `/rq/rqcard/proxy/api/iam/users`） | 403 `PROXY_PATH_DENIED` |
| SEC-03 | 🔴 | 带头请求 `/rq/rqcard/proxy/api/panel/stream`（SSE） | 403（SSE 不透传）；面板前端自动降级轮询 |
| SEC-04 | 🟠 | 未配置连接时带头请求任意代理路径 | 409 `NOT_REMOTE` |
| SEC-05 | 🔴 | 记下 WIZ-02 消费前的一次性初始口令；完成初始化后手工把口令文件还原回数据目录，再走一次初始化 | 初始化失败（初始口令已被改密失效），不可重放建立会话 |
| SEC-06 | 🟠 | 同一 `entry_ticket` 兑换两次（第二次可 curl 重放） | 第二次 400 `ENTRY_TICKET_INVALID`（一次性） |
| SEC-07 | 🟠 | 带 `?entry_ticket=` / `#entry_ticket=` 打开面板 | 兑换后地址栏票据即被清除（query 与 fragment 两种形态都清），刷新页面不重复兑换 |

## 5. 验收边界（先读再提单：以下为**预期行为或范围外**，不算缺陷）

| # | 边界 | 说明 |
|---|---|---|
| B-1 | **钉钉扫码后停留在宿主页 = 预期降级** | 跨源自动回跳（扫码完成自动回本机 dsh）依赖**宿主侧 G1 增强**（可信跨源 next + 自助 entry_ticket，已登记 `docs/handoff-f-remainder-to-main.md` 待主分支采纳）。采纳前：向导打开的地址**必须**携带 `next`（AUTH-04 核对），且「我已完成扫码」诚实指引可用（AUTH-05/06）——这两点在验收范围内；自动回跳本身不在本轮（宿主上线后补测 AUTH-09）。 |
| B-2 | **拷贝安装形态范围外** | `dsh plugin add github:`（拷贝进 node_modules）受 Node 拒解析 node_modules 内 TS 的**架构级限制**（交接清单 G3）。本轮只验源码/link 安装形态；拷贝形态不测、不提单。 |
| B-3 | **远端形态实时通道为 30s 轮询 = 契约** | 代理不持流：远端形态 SSE 被显式拒绝（SEC-03），前端自动降级 30s 轮询，界面出现轮询/降级角标是**正确行为**。本机形态（E1）SSE 直连可用。 |
| B-4 | **插件不热改宿主监听** | 向导「选择对外 IP」只产出 `--trusted-host` 指引命令；按指引重启 dsh 后局域网可达才算通过（WIZ-06），当场不生效不是缺陷。 |
| B-5 | **宿主面功能范围外** | 控制台/平台管理（用户管理、审计、计费等）归上游主分支（双轨边界）。本清单只测：面板 + 连接 + 权限**消费侧**。宿主面问题登记并注明「回流主分支」，不阻塞本清单出口。 |
| B-6 | **钉钉生产凭据** | 真实扫码/群桥推送依赖宿主钉钉连接器配置；未配置场景按 DD-01 空态判定。 |
| B-7 | **模型单轮非流式 = 契约** | 面板协作会话/工具调用为单轮非流式（G2 流式化待主分支，未采纳）。 |
| B-8 | **兼容口径** | dsh `0.1.0-rc.7`（`>=0.1.0-rc.7 <0.2.0`）、Node ≥ 22.6、现代 Chrome/Edge；其余版本/浏览器不在本轮矩阵。 |

**诚实降级文案对照**（出现即正确，勿提 P1）：探活不可达提示；HTML 兜底的 502 提示；「无法跨站带回…请用账号密码登录」；「未接入模型」；部门范围受限 403 文案。
